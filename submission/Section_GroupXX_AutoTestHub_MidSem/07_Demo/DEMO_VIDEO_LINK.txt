PART 2: BRIEF EXPLANATION OF THE PROBLEM (0:45 – 1:30)
SPEAKER: Ishree (Frontend Lead)
--------------------------------------------------------------------------------
[VISUAL: Slide 2 — Problem diagram highlighting flaky scripts, driver version mismatch, and complexity]
"Modern web applications undergo frequent releases, requiring rigorous regression testing.
However, writing and maintaining raw Selenium automation scripts introduces significant friction:
1. First, asynchronous DOM rendering causes timing flakiness and false-negative failures.
2. Second, constant Chrome browser updates cause WebDriver binary incompatibilities.
3. Third, most existing tools either require writing heavy boilerplate code or are proprietary,
   bloated enterprise suites inaccessible to agile development teams.
There was no simple, declarative platform that seamlessly bridges web dashboards, REST APIs,
and headless browser workers. That is the exact problem AutoTestHub solves."

--------------------------------------------------------------------------------
PART 3: OVERVIEW OF THE PROPOSED SOLUTION (1:30 – 2:15)
SPEAKER: Shifa Siddiqui (Backend & Database Lead)
--------------------------------------------------------------------------------
[VISUAL: Slide 3 — Solution overview highlighting declarative JSON tests and multi-tier design]
"AutoTestHub provides a declarative, JSON-driven web automation platform. Instead of writing
imperative code, testers define browser actions — such as navigating to a URL, typing text into
forms, clicking elements, and asserting titles — in simple JSON schemas.
Our platform ingests these schemas via REST endpoints, manages database persistence in MongoDB,
and orchestrates isolated browser execution sessions with guaranteed cleanup, dynamic locators,
explicit waits, and automated screenshot evidence capture."

--------------------------------------------------------------------------------
PART 4: SYSTEM ARCHITECTURE & IPC BRIDGE (2:15 – 3:15)
SPEAKER: Shristi Neekhra (Integration Lead)
--------------------------------------------------------------------------------
[VISUAL: Screen Share — Architecture Diagram (Architecture_Diagram.pdf)]
"To achieve this, we developed a 4-tier decoupled architecture:
- At the top is the Presentation Tier: our Selenium Control Desk web UI.
- Beneath that is the Backend Gateway: built on Node.js and Express, exposing endpoints like
  POST /api/tests and POST /api/tests/:id/run.
- Connected to Express is our asynchronous Execution Service. When a test is triggered, Node.js
  spawns an isolated Python 3 child process, piping the test JSON directly into its standard input.
- In the engine tier, our Python Selenium worker reads the payload, validates safety rules,
  and manages Chrome WebDriver using Selenium Manager.
- Output results are emitted as a single-line JSON payload on stdout, which Node.js extracts
  via regex and saves to MongoDB, while all logging goes cleanly to stderr."
